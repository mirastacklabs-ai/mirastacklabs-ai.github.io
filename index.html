ai.governance

The AI Governance Gap

Deploying un-governed AI agents into production infrastructure is a major security and operational risk. MIRASTACK LABS authored the open-standard EGAProtocol to enforce strict, wire-level discipline on every agentic action.

UNGOVERNED RISK

Consumer-Grade Agentic AI

Standard agentic frameworks (LangGraph, AutoGen, direct LLM tool calling) lack intermediate governance. The LLM issues direct tool calls that execute raw code, database updates, or system modifications without validation.

1. SRE Prompt
↓
2. LLM Provider (Inference)
↓
3. Direct tool_call (Un-governed)
↓
4. Execution on Production Ecosystem
  • No wire-level identity propagation or authentication.
  • Bypassable, application-level approval checks.
  • No immutable audit trails for regulatory compliance.
  • High risk of runaway, destructive loops on databases, Kafka, and servers.
EGA-GOVERNED

EGAProtocol Governed Architecture

MIRASTACK is the reference implementation of EGAProtocol. The MIRA Engine acts as a stateless security proxy, intercepting and validating every agentic action at the wire level.

1. SRE Prompt
↓
2. MIRA Engine (EGA Interceptor)
↓
3. Governed LLM / Agents SDK Dispatch
↓
4. Secure Execution on Production Ecosystem
  • Cryptographically verifiable identity on every message envelope.
  • Mandatory human-in-the-loop approval primitives built into the wire protocol.
  • Immutable audit trails following OpenTelemetry semantic conventions.
  • Strict permission scopes (READ, WRITE, MODIFY, ADMIN) enforced on every action.

Ten things the factory does

Sovereignty by construction

Runs where your data must stay. No outbound call is required for the platform to function.

Provable at the network layer, not promised in a contract.

Governance at the gate

Every plugin execution and every MCP tool call passes one approval gate before dispatch.

The gate's pass object cannot be constructed outside its own package. A bypass fails the build.

MCP inside the perimeter

MCP servers become governed runtimes in networks with no internet route.

The child process must bind loopback. Never 0.0.0.0.

Your models and the frontier

Self-host open-weight models. Reach frontier APIs through the same router, RBAC, and audit trail.

One provider process, one tenant, for its entire lifetime.

Complete token accounting

Prompt and completion tokens, cost, and latency recorded per turn — whether the response streamed or buffered.

Both paths report through a single accounting chokepoint, so they can never diverge.

Policy routing

Route to self-hosted models by default. Escalate to frontier by explicit policy, including data classification.

Regulated payloads never leave the perimeter, by rule rather than by convention.

Identity and attribution

Every action an agent takes is attributable to a named human principal.

Unattributed dispatch is refused, not logged.

Enforced human-in-the-loop

Approvals are single-use, signature-verified, and bound to the exact action hash.

The requester cannot approve their own request. Enforced in the engine, not the frontend.

Agents with scoped tools

Personas with explicit tool mappings. Only classified, approved tools reach the planner.

A tool's own annotations are evidence, never authority.

Compliance evidence

Governance events map to the control frameworks your auditor already uses.

An evidence pack, not a log export.

open.foundation

Built on an Open Core

The MIRA Framework — a Go-native, Apache 2.0 licensed agentic orchestration framework — is the open-source substrate beneath the MIRASTACK platform. Built for platform engineers who operate in environments where air-gap compliance and operational reliability are non-negotiable.

Open-sourcing the framework creates a community that extends tool adapters and model integrations faster than any single team can. It establishes MIRASTACK as the standard for sovereign AI infrastructure orchestration.

Apache 2.0 Go-Native Air-Gap First Single Binary No Cloud APIs Typed State Human Governance EGAProtocol Open Spec

MIRA Engine runs on Kubernetes — with its own in-memory stream layer for fast graph execution and kine + MariaDB as the config store. No etcd cluster. No exotic dependencies. No cloud APIs. If your environment already runs Kubernetes and MariaDB, MIRA adds almost zero new operational surface.
