Identity, RBAC and Attribution

the.role.model

The role model

MIRASTACK uses a hierarchical role model with tenant-level isolation. Roles are assigned to human principals, not to agents. Agents inherit capabilities through their persona definition, which is approved and governed by an operator.

The platform does not create a parallel identity system. It integrates with your existing identity provider via SSO and SCIM. Users, groups, and roles sync from the source of truth. When a user is deprovisioned, their access is revoked across every tenant and every runtime immediately.

sso.and.scim

SSO and SCIM

Single sign-on via SAML 2.0 or OIDC. User provisioning and deprovisioning via SCIM 2.0. The platform acts as a service provider — it does not store passwords or create a separate credential store.

SSO is enforced at the API gateway. Every request — from the UI, the CLI, or an agent SDK — must present a valid token. The token maps to a principal, the principal maps to a role, and the role maps to permissions. If any link in that chain is missing, the request is refused at the gateway. It never reaches the runtime.

tenant.isolation

Tenant isolation

Every tenant runs in its own namespace with isolated state, secrets, and telemetry. A tenant cannot see or influence another tenant's models, agents, or audit trail. Isolation is enforced at the network, storage, and runtime layers.

Multi-tenancy is not a shared database with row-level security. It is a separate control plane per tenant, with separate provider processes, separate approval queues, and separate ledgers. The only shared infrastructure is the physical hardware and the Kubernetes scheduler.

attribution

Attribution and refusal of unattributed dispatch

Every action an agent takes is attributable to a named human principal. If the principal is missing — because the token expired, the user was deprovisioned, or the agent tried to spoof identity — the dispatch is refused, not logged.

Attribution is not a log field that can be stripped. It is a cryptographic binding between the action hash, the signer's key, and the approval token. The ledger entry cannot be constructed without all three. An unattributed dispatch is refused at the gate before it consumes any compute or touches any state.
