The Engine Governed Agents Protocol

EGAProtocol is the open specification that turns every agentic action into a governed, attributable, and replayable event. It was designed for environments where bypassing governance must be a compile error, not a policy violation.

why.a.protocol

Why a protocol and not a library

Libraries run inside the process they govern. A malicious or compromised agent can patch around them, skip their calls, or run a separate execution path entirely. A protocol lives at the wire boundary. It sees every dispatch before it executes, and it cannot be bypassed without breaking the connection itself.

EGAProtocol is not a Python decorator, a LangChain callback, or an AutoGen hook. It is a disciplined contract between the agent runtime and the execution substrate. Every plugin call, every tool call, every agent-to-agent message passes through one gate. That gate is the only path to execution.

permission.classes

Four permission classes

Every action an agent takes is classified before dispatch. The classification is set by the operator, not inferred from the payload. Four classes cover every possible side effect an enterprise agent can produce.

READ

Observation only

Queries, searches, metadata lookups, and read-only API calls. No state is modified. Audit log records the query, the target, and the actor.

WRITE

Create and append

New records, messages, tickets, and artifacts. Append-only semantics where possible. Existing state is not altered. Actor and content hash are recorded.

MODIFY

Update existing state

Configuration changes, record updates, permission changes. Requires explicit operator approval unless the policy engine has a standing rule for this actor and this target.

ADMIN

Structural changes

Schema changes, account creation or deletion, access control modifications. Always requires a single-use, signature-verified approval bound to the exact action hash. The requester cannot approve their own request.

enforcement.ordering

Enforcement ordering

Governance is not a middleware layer that can be reordered or skipped. It is the dispatch path itself. When an agent issues a tool call, the runtime does not execute the tool — it submits the dispatch to EGAProtocol first.

1. Agent emits tool_call
↓
2. EGAProtocol classifies the action
↓
3. Policy engine evaluates standing rules
↓
4. Approval gate if required
↓
5. Dispatch recorded on the ledger
↓
6. Tool executes inside the runtime

Step 5 writes the pass object to the audit ledger before step 6 begins. If step 6 fails, the ledger still records the attempt, the actor, the target, and the reason. Every token, cost, and latency metric from the execution is attached to that same ledger entry.

approval.primitives

Approval primitives

Approvals in EGAProtocol are not frontend buttons. They are cryptographic primitives that live in the governance engine. Every approval is single-use, signature-verified, and bound to the exact action hash it authorises.

› Single-use tokens. Once an approval is consumed, it cannot be replayed against a different action hash or a different session.
› Actor separation. The requester and the approver must be distinct principals. Self-approval is refused at the engine level, not filtered in a UI.
› Time-bound validity. Approvals expire after a configurable window. Expired approvals require a new request and a new approval flow.
› Revocation propagation. Revoking a principal invalidates all outstanding approvals in flight. The effect is immediate across every tenant and every runtime.
open.specification

Open specification and stewardship

EGAProtocol is published as an open specification under MIRASTACK stewardship. The protocol defines the contract, the message formats, and the state machine. Implementations may vary, but the wire discipline does not.

The specification is versioned. Breaking changes to the protocol require a new major version. Backwards compatibility is maintained for at least two prior major versions in every release. This gives enterprises the upgrade cadence they need for regulated environments without locking them to a single vendor runtime.

MIRASTACK Labs maintains the reference implementation and the test harness. The community may submit implementations in any language, provided they pass the conformance suite. That suite is part of the open specification.
